# Pac-Man – Dev Diary – 2026-08-26

### What was done
- Finished integrating the maze generator package switch: `build_maze()` in
  `server.py` now uses the `.maze` property of `MazeGenerator` directly
  (previously incorrectly called `.generate_maze()`, which doesn't exist),
  `cells_to_grid()` processes the bitmask grid of the new package.
- Fixed a server shutdown bug: `os.getpgrid(0)` doesn't exist in Python, the
  correct call is `os.killpg(os.getpgid(0), signal.SIGTERM)`.
- Fixed a Makefile bug that was responsible for the persistent "still running
  under Python 3.9 anyway" error: `uv venv` doesn't overwrite an existing
  venv directory. The `install` target now deletes the old venv first
  (`rm -rf $(VENV_NAME) &&`) before recreating it with `--python 3.12`. This
  finally gets `mazegenerator` (uses `str | bool` syntax, needs Python
  >=3.10) running in the correct interpreter.
- Added a pause feature: pressing "P" toggles `GameState.paused`,
  `move_player()`/`tick()` bail out early when paused, new `#pause-screen`
  with Resume/Back-to-Main-Menu buttons in `index.html`.
- Fixed a bug with the "Back to Main Menu" button: previously it only
  switched the screen locally without informing the server -> the next
  periodic broadcast still came in with `paused: true` and re-overlaid the
  pause screen. Fix: new `leave_to_menu` action/method that resets
  `paused`/`started` server-side.
- Made the ghost AI "dumber": `GHOST_CHASE_CHANCE` (default 0.6) – ghosts
  only chase deliberately via BFS with this probability, otherwise they move
  randomly (`_random_valid_step`).
- Player speed cap: movement keys fired too fast when held down due to
  browser key-repeat -> `MOVE_INTERVAL_MS` throttle in `game.js` (default
  150ms) limits the movement rate independent of key-repeat.
- Fully implemented edible-ghost mode: a power pellet sets `edible_until`
  (a `time.monotonic()` timer, `EDIBLE_DURATION` seconds), ghosts flee during
  that time (`_flee_step`, maximizes instead of minimizes the distance to
  the player), colliding with an edible ghost awards `POINTS_PER_GHOST`
  points and only respawns the ghost at its starting corner instead of
  costing a life.
- Added level progression: new `level` field in `GameState`, `level_complete`
  is set once gums and power pellets are empty, `next_level()` increments the
  level, loads a fresh maze (new random seed), and keeps score/lives.
  `server.py` generates a new maze after each move when needed and calls
  `next_level()`.
- Extended the highscore system with level: `config_loader.add_highscore()`/
  `load_highscores()` now also save/read `level` per entry,
  `GameState.recorde_highscore()` passes along the current level.
- New `/highscores` endpoint + highscore screen in the frontend (button on
  the start screen), shows entries as "Name - Stage X - Score points".
- The live HUD now additionally shows the current level, ghosts turn blue
  during edible mode.
- Discussed a fix (code not yet written): the maze generator draws a "42"
  logo in the middle of the maze out of isolated, unreachable tiles.
  `_place_gums()` was still placing gums there that could never be collected
  -> `level_complete` never triggered, level 2 was unreachable. Solution: new
  `_reachable_cells()` method (flood fill/BFS from the player start),
  `_place_gums()` now only places gums/power pellets on reachable tiles.

### Problems / bugs (fixed during the session)
- `generator.generate_maze()` doesn't exist on `MazeGenerator` (correct:
  the `.maze` property) -> `AttributeError` on server startup after the
  package switch.
- `os.getpgrid(0)` doesn't exist in Python (correct:
  `os.killpg(os.getpgid(0), ...)`) -> the shutdown endpoint crashed.
- `TypeError: unsupported operand type(s) for |: 'type' and 'type'` on
  startup: the server was running under Python 3.9 (Xcode-bundled Python)
  instead of the 3.12 venv, because `uv venv` doesn't overwrite an existing
  (broken) venv directory – the venv from the first failed attempt stayed
  stuck on 3.9, even though `--python 3.12` was already in the Makefile.
- Pause feature: the initial suspicion was a wrong key check (Escape instead
  of P) – actually P was correct as intended from the start, not a real bug.
- "Back to Main Menu" briefly showed the start screen and then jumped back:
  the server knew nothing about the menu change, the periodic broadcast with
  `paused: true` reactivated the pause screen. Fixed with an explicit
  `leave_to_menu` action.
- `_check_collision()` only printed "Game Over" from `_respawn_after_hit()`
  instead of setting `self.game_over` -> the game-over screen appeared with
  up to 300ms delay (next tick). Fixed directly while reworking for edible
  ghosts.
- Level 2 was never reachable: gums were also placed in the unreachable "42"
  logo in the middle of the maze, so `self.gums` was never empty. See the fix
  above (`_reachable_cells()`).
