# Pac-Man – Dev Diary – 2026-09-29

### What was done
- Replaced the half-working Escape-key prototype (wrong screen id, missing
  import, a dead-code duplicate `case "leave_to_menu"` on the backend that
  could never run) with a proper exit flow: pressing Escape now opens a
  menu styled like the pause screen, but with **RESUME** and **EXIT**
  instead of continue/home. It works both mid-round (overlaid on top of
  the canvas, same as the pause screen) and from the main menu, and
  toggles closed again on a second Escape or the RESUME button, restoring
  whatever screen was showing before (`state.screenBeforeExit` in
  `screens.js`).
- Pressing EXIT sends a new `exit_game` websocket action, shows a
  "GAME CLOSED" screen, and the backend shuts the whole server process
  down (`os.killpg(..., SIGTERM)` after a short delay, same pattern as
  the existing `/shutdown` HTTP route).
- Once the "GAME CLOSED" screen is up, all further input is ignored —
  added a `state.gameClosed` flag that both `handleKeydown()` and
  `handleSocketMessage()` bail out on immediately, so no keypress or late
  tick from the dying server can do anything anymore.
- Centered the new exit menu / game-closed screen: they were missing from
  the CSS selector list that gives the other overlay screens (`#pause-screen`,
  `#overlay`, etc.) their `display:flex; align-items:center;
  justify-content:center`, so they were rendering pinned to the top of the
  viewport instead of centered. Added a matching `.hero-btn-red` style for
  the EXIT button.
- Small unrelated fix noticed on the way: `state.time` could go visibly
  negative in the HUD for a tick right around game-over — now clamped to
  `0` in `socket-handlers.js`.
- Tested the whole flow live (main menu -> Escape -> Exit, and mid-round ->
  Escape -> Exit) and confirmed the server process actually exits
  afterwards.

### Problems / bugs (fixed during the session)
- The Escape-menu prototype from before wasn't wired up correctly at all
  (`showScreen("leave_to_menu-screen")` pointed at a nonexistent id, and
  `openLeaveToMenuScreen` was called without being imported) — would have
  thrown at runtime the first time someone hit Escape.
- The backend had two `case "leave_to_menu":` branches in the same
  `match` statement; the second one (the one that actually killed the
  server) was unreachable dead code.
- New exit/game-closed screens weren't centered because they weren't
  added to the shared centering selector in `style.css`.
