# Pac-Man – Dev Diary – 2026-09-23

### What was done
- Fixed the Linux/`python3` startup path from yesterday: `pac_man.py` now
  builds the full setup command itself (`rm -rf venv && uv venv --python
  3.12 --seed && source venv/bin/activate && pip install -r
  requirements.txt && uvicorn ...`) instead of assuming an already-activated
  venv, and the Makefile's `osascript` call was fixed to actually `source`
  the venv before installing. `pac_man.py` also opens the game in Chrome
  automatically ~10s after launch, once the server should be up.
- Big backend refactor: split the old monolithic `backend/game_logic.py`
  (434 lines) into a new `backend/Gamestate/` package (`gamestate.py`,
  `ghost.py`, `ghost_movement.py`, `private_gamestate.py`), updated the
  imports in `server.py` accordingly, then removed the old `game_logic.py`
  (kept as `_game_logic.py` for reference/backup).
- Translated `index.html` to English.
- Frontend: added arrow-key movement and capital-letter (Shift+WASD)
  movement to `KEY_TO_DIRECTION` in `game.js`.
- Implemented the Konami-code detection for the cheat mode on the frontend:
  new `cheat_list`/`cheat_check` arrays and `check_input_cheat()` in
  `game.js`, comparing each keypress against the next expected step of the
  Up-Up-Down-Down-Left-Right-Left-Right sequence, resetting on a wrong key.
  Once the full sequence is entered, `handleKeydown()` sends a
  `{ action: "cheat_activate" }` message over the websocket.
- Added the matching `case "cheat_activate"` branch to the websocket handler
  in `server.py` as the entry point for the cheat logic on the backend – the
  actual gameplay effect (making the player/ghosts behave differently) was
  still a TODO at this point.
- Removed the committed `uv.lock` and leftover `__pycache__` folders from
  git tracking.
- Translated the existing dev-diary entries (old `doc/2026-07-23.md` etc.)
  to English and renamed them to the `lunsold YYYY-MM-DD.md` pattern used
  from now on.
