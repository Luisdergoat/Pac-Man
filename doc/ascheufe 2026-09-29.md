# Pac-Man – Dev Diary – 2026-09-29

### What was done
- `mypy` fix in `loader.py` (`5d3c87d`): typed `DEFAULT_CONFIG` as
  `dict[str, int | str]` and `get_config_path() -> str`.
- Renamed `pac_man.py` to `pac-man.py` and updated the usage message
  (`b06a176`). Removed the unnecessary global `CONFIG_PATH` and
  `get_config_path()` from `loader.py`, the config path is now only
  handed over as a function argument (error messages use `config_file`).
- Cleanup (`bcf4aea`): removed `from __future__ import annotations`,
  commented-out constants, the unused `BASE_DIR`/`Path` import and sorted
  the module constants in `game_logic.py`.
- Makefile: `ENTRY` changed to `pac-man.py` (`414ae1a`), and the `debug`
  target now uses `python3 -m pdb` instead of the broken `python3 pdb`
  (`fe04499`).
- Removed an unused print in `server.py` (`14e1839`).
- Fixed hardcoded highscores (`9383a70`): `submit_name` and the
  `/highscores` endpoint used `"highscores.json"`, now they use
  `config["highscore_filename"]`. The message for a missing highscore file
  is now "not created yet" as this is a normal case.
- Cheat mode reset (`97f6f42`): `cheats_enabled` is reset on a new game
  (`reset`). Power pellet bug: `next_level()` no longer resets
  `edible_until` if it is `inf` (cheat mode), so ghosts stay edible.
- Boolean issue (`5bf7096`): `True`/`False` are `int` in Python, so a
  config value or a highscore `score`/`level` of `true` was accepted as a
  number. The config parser and the highscore parser now explicitly
  reject `bool`.

### Problems / bugs (fixed during the session)
- Highscore file name was hardcoded in two places, ignoring the config.
- Cheat mode stayed on after a restart.
- Level change removed the "edible" state from cheat mode.
- `make debug` did not work (`python3 pdb` instead of `python3 -m pdb`).
- `bool` values passed the `isinstance(v, int)` checks.
