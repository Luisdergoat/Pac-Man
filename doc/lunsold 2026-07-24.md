# Pac-Man – Dev Diary – 2026-07-24

### What was done
- Switched ghost AI from naive greedy behavior (only direct neighbor cells,
  straight-line distance to the player) to real pathfinding: `bfs_next_step()`
  in `game_logic.py` uses breadth-first search to find the actual shortest
  path through the maze, and ghosts now only take the first step of it – no
  more running into walls/dead ends.
- Ghost-ghost collision: each tick an `occupied` set is built from the
  current ghost positions, and every ghost gets it as a `blocked` set for
  pathfinding, so two ghosts never end up on the same tile.
- "Nothing moves until the player takes the first step": new `started` flag
  in `GameState`, `tick()` bails out as long as `started == False`,
  `move_player()` sets it on the first keypress.
- Added pac-dots + power pellets + scoring: `_place_gums()` distributes small
  dots on all free tiles and power pellets in the 4 corners, `_collect_gums()`
  collects them and awards points (`POINTS_PER_GUM`, `POINTS_PER_SUPER_GUM`).
- Edible-ghost mode: a power pellet sets `edible_until` (a timer via
  `time.monotonic()`), ghosts flee during that time
  (`_move_ghost_away_from_player`, greedy – maximizes instead of minimizes
  the distance), hitting an edible ghost counts as "eaten" (`Ghost.eaten`),
  awards points (`POINTS_PER_GHOST`), and the ghost respawns at its starting
  corner after `GHOST_RESPAWN_DELAY` seconds.
- Highscore system in `config_loader.py`: `load_highscores()`/
  `add_highscore()` read/write a JSON list, validate name (max. 10
  characters) and score (non-negative int), keep the top 10, robust against a
  missing/broken file. `GameState.game_over` flag informs the frontend when
  the game is over.
- Custom config system (`config_loader.py`, `config.json`): JSON with comment
  lines (`#`/`//`), its own keys separate from the `mazegen` `config.txt`
  (lives, points per gum/ghost, `level_max_time`, highscore file).
- Restart feature: pressing "R" (or a button) sends a `restart` action over
  the WebSocket, `GameState.reset()` resets score/lives/flags and re-places
  player/ghosts/gums. `regenerate_maze()` in `server.py` re-parses
  `config.txt` and calls `generat_maze()` fresh (needs its own `Cell` grid,
  since old cells already have a "visited" status) – thanks to `SEED=random`
  in config.txt, this produces a completely new maze each time.
- Complete UI overhaul: start screen ("Game Start"/"Settings"), settings
  screen, loading screen, and game-over overlay as their own "screens" with a
  shared `showScreen()`/`hideAllScreens()` logic. The loading bar is a
  deliberately faked "indeterminate progress" element: it grows slowly via
  CSS transition (decelerating, `cubic-bezier`) up to 92% and stays stuck
  there until the real maze data arrives – then a class switch to
  `.complete` makes the width jump straight to 100% without a transition
  ("snap"). The game-over overlay now has a name field + "Save Score"/"Play
  Again" instead of an ugly `prompt()`.
- Exit-game button on the start screen and game-over overlay: sends
  `POST /shutdown`, the server kills itself after a short delay via
  `os.killpg(os.getpgid(0), signal.SIGTERM)` (kills the process group so that
  with `uvicorn --reload` the watcher process dies too, not just the
  worker).
- `Makefile` in the project root: `install` builds a venv via `uv venv` +
  installs requirements, `run`/`make` (default target) automatically opens a
  new terminal window (`osascript`/AppleScript on macOS), starts the server
  in it, and then opens Chrome at `localhost`. Also `debug` (pdb),
  `lint`/`lint-strict` (exactly the flake8/mypy flags required by the
  subject), `clean` (caches), `fclean` (also deletes the venv), `re`.
- Received the assigned A-Maze-ing package
  (`mazegenerator-00001-py3-none-any.whl` in the project root) – replaces the
  previous hand-written `mazegen` folder. Unpacked the wheel and checked the
  source code directly (not just trusting the README): class
  `MazeGenerator`, constructor `size=(w,h), entry_cell, exit_cell, perfect,
  seed` (seed=0 means fully random), property `.maze` returns a `maze[y][x]`
  grid without an extra border (outer edges are hard-coded into the border
  cell bits), wall bits **N=1, E=2, S=4, W=8** (different from the old
  package: N=8, E=4, S=2, W=1). `cells_to_grid()` in `server.py` was
  rewritten accordingly (no more `+1` offset needed to hide a border). Maze
  generation now goes directly through constructor parameters in Python, no
  more `config.txt`/`parse_maze_config` detour needed for the maze part.
  Added the package as a local wheel file in `requirements.txt`
  (`../mazegenerator-00001-py3-none-any.whl`).

### Problems / bugs (fixed during the day)
- Ghosts "twitched" against walls: greedy distance-based movement without
  real pathfinding got stuck in dead ends -> replaced with BFS.
- `_strip_coments()` in `config_loader.py` used
  `line.strip().startswith("#", "//")` – the second argument of `startswith`
  is a start index (int), not a second prefix string -> TypeError, comments
  were never stripped. Fix: `startswith(("#", "//"))` with a tuple.
- The `save_highscore` method was only half-written (broke off mid-`if`) ->
  SyntaxError on startup, the server didn't run at all.
- The highscore "not being saved" wasn't actually a bug – there were two
  files (`highscore.json` empty in the root as a dead default value,
  `backend/highscores.json` actually populated), just checked in the wrong
  place.
- `game.js`: `document.getElementById("name-submit")` – but the button is
  named `submit-name-btn`, a typo crashed the `onmessage` function halfway
  through.
- The "R" key set `gameOverHandled = false` immediately on keypress, before
  the server response arrived -> the state-driven logic to hide the overlay
  never fired, the game-over screen stayed stuck. Fixed by the central
  `showScreen()`/`hideAllScreens()` principle instead of scattered class
  toggles.
- `style.css` had duplicate, conflicting rules for `.screen` and
  `#loading-bar-fill`/`#loading-bar-track` (old version was appended instead
  of replaced) -> the loading bar effectively had `width: 0%`, was
  invisible.
- Makefile: the `osascript` call for `run` was split incorrectly (unclosed
  quotes, `unexpected EOF`) and mistakenly filed under `install`; commands
  meant to run in the newly opened terminal all have to be ONE string inside
  `do script "..."` (chained with `&&`) – otherwise each separate recipe line
  in the Makefile runs in the Makefile's own shell, not in the new window.
- `game.js`: an incomplete function call `finish` instead of
  `finishLoadingAnimation();` -> ReferenceError on every round start, broke
  `onmessage`, the game stayed stuck on the loading screen.
- The exit button on the start screen was outside `#start-screen`/
  `.screen-box` in the HTML -> was permanently visible instead of only on
  the start screen.
- Package switch: the README quickstart for the assigned `mazegenerator`
  wheel is wrong/outdated (`from mazegenerator import MazeGenerator` fails,
  `__init__.py` in the wheel is empty and exports nothing). The actually
  working import is: `from mazegenerator.mazegenerator import
  MazeGenerator`. Only found by testing directly in the sandbox Python, not
  apparent from the docs.
