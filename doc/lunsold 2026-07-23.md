# Pac-Man – Dev Diary – 2026-07-23

### What was done
- Hooked up the maze generator (`A-Maze-ing` package `mazegen`) to the backend:
  `server.py` parses `config.txt`, builds the maze via `mazegen_algo.generat_maze`
  and converts the corridor maze (`Cell` objects with N/E/S/W wall bitmask) into
  a simple 0/1 block grid (`cells_to_grid`) that's easy to render.
- Frontend (`frontend/src/game.js`, `index.html`, `style.css`) draws the maze on
  a `<canvas>`, scales dynamically to the window size (`fitCanvasToWindow`), and
  centers title + canvas via flexbox.
- Architecture overhaul: game logic (player movement, ghost AI, collision) now
  runs entirely in Python (`backend/game_logic.py`), no longer in JS.
  Communication happens over WebSocket (`/ws`): the server holds the
  `GameState`, pushes a tick update every 300ms, the client only sends key
  presses.
- Ghost skeleton is in place: 4 ghosts spawn at the 4 corners of the maze
  (red, pink, cyan, orange – as seen in the screen recording), simple chase AI
  (moves each tick in the direction that most reduces the distance to the
  player), collision costs a life and respawns the player in the center of the
  maze.
- The uploaded screen recording (`IMG_1435.mp4`) shows the current state: the
  maze renders correctly (blue walls, white corridors), title "Pac-Man", all 4
  ghosts stand at their spawn points in the corners. The player (black square)
  sits at a cell in the left half of the maze in the video – nothing moves in
  the video, so it's probably just a brief state snapshot, no movement
  visible. The video had audio (not transcribed – let me know if that's still
  needed).

### Problems / bugs (fixed during the day)
- The `/maze` endpoint returned raw `Cell` objects instead of a clean grid ->
  fixed with `cells_to_grid`.
- `style.css` 404 due to a wrong path (`href="style.css"` instead of
  `href="static/style.css"`) – StaticFiles is mounted under `/static`.
- Canvas was fixed at 800x600, and later mistakenly set to 2000x2000, while
  the maze grid only needed ~1150px -> the maze hung in the corner of the
  canvas, looked "not centered". Fixed via dynamic `fitCanvasToWindow()`.
- Body flexbox without `flex-direction: column` -> title/text sat side by
  side instead of stacked and centered.
- During the switch to Python logic: `DIRECTIONS: Dict[...] = {...}` got
  mistyped as `DIRECTIONS = Dict[...] = {...}` (colon mistyped as `=`) ->
  TypeError on startup.
- The `websockets` package was installed in Python 3.9 (system Python)
  instead of the `.venv` (Python 3.12) that uvicorn actually uses -> "No
  supported WebSocket library" warning, `/ws` returned 404.
- `GameState.__post_init__` had been renamed to `position()` and was never
  called anywhere -> player/ghost starting positions were never set.
- `to_dict()` sends the grid under the key `"grid"`, but JS was checking
  `data.maze` -> mismatch, the maze never made it to the frontend.
- `draw()` in JS still used old local `x`/`y` (fixed at 100) for the player
  and `g.x`/`g.y` for ghosts instead of the `player.row/col` and
  `ghost.row/col` coming from the server -> player invisible (far outside the
  canvas), ghosts invisible (`NaN` coordinates).
