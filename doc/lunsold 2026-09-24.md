# Pac-Man – Dev Diary – 2026-09-24

### What was done
- Fixed the websocket endpoint mismatch that broke the live connection
  ("ws needs endpoint") so the frontend reliably connects to `/ws` again.
- Frontend refactor: split the single, by now very large `game.js` into a
  `scripts/` folder – `state.js` (canvas/ctx, the websocket, constants and
  one mutable `state` object for everything that used to be loose globals
  like `player`, `grid`, `score`, `lives`, ...), `rendering.js` (`draw`,
  `drawPacman`, `drawGhost`, `fitCanvasToWindow`), `highscores.js`,
  `screens.js`, `socket-handlers.js` and `controls.js` (input handling,
  cheat detection, round management). `game.js` itself is now just the
  entry point that imports everything and wires up the event listeners
  (~425 lines shorter). `index.html`'s script tag was switched to
  `type="module"` so the imports actually work.
- Started wiring up the config loading: `src/loader/loader.py` now points
  `CONFIG_PATH` at the real project root (`config.json` in the repo root –
  it was pointing at a non-existent `src/config.json` before), and
  `game_logic.py` began reading `points_per_pacgum` /
  `points_per_super_pacgum` / `points_per_ghost` from `load_config()`
  instead of hardcoded constants.
- Finished getting the config to load correctly: `GameLogic` now calls
  `load_config()` on initial setup (new `GameState.init_lives()`) and again
  on every restart, so `lives` from `config.json` actually determines how
  many lives the player starts with, instead of the old hardcoded
  `self.g_state.lives = 3`. Verified with a test value of `"lives": 67` in
  `config.json`.

### Problems / bugs (fixed during the session)
- After splitting up `game.js`, the websocket briefly stopped finding its
  endpoint until the endpoint path was corrected.
- `config.json` was being read by `load_config()` the whole time, but
  nothing in the game logic ever actually used the returned values – the
  game silently always ran with the hardcoded defaults regardless of what
  was in the config file. Root cause was partly the wrong `CONFIG_PATH`
  (pointing into `src/`), partly that nothing called `load_config()` in
  `game_logic.py` at all yet.
