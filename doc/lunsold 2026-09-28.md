# Pac-Man – Dev Diary – 2026-09-28

### What was done
- Finally fixed the "have to enter the cheat combo twice" bug from
  Thursday: `check_input_cheat()` in `controls.js` was comparing against
  a snapshotted `expected_input` instead of re-reading
  `state.cheat_check[0]` after resetting it, and never reset
  `state.cheat_check` back to the full list once a cheat activation
  succeeded — so the very next keypress after activating was silently
  "half consumed" against a stale/empty check array. Now it re-reads the
  live array and always resets it on a full match, on or off.
- Implemented a real game timer: `GameLogic.tick()` now counts
  `level_max_time` down (`-= 0.5` per tick) and sets
  `State.TIMEDOUT` once it hits zero; the value is broadcast to the
  frontend as `time`, rendered in a new "TIME" stat block in the HUD, and
  updated every tick in `socket-handlers.js`.
- Added a matching, more specific game-over message: `data.game_over`
  distinguishes `1` (no lives left -> "No lives left! Game Over!") from
  `2` (timed out -> "Time's up! Game Over!"), shown via the new
  `#game_over_tag` element on the overlay screen instead of a hardcoded
  "GAME OVER" for every case.
- Cleaned up `leaveToMenu()` (pause menu's HOME button) so it also hides
  the canvas/scoreboard and clears the canvas before showing the start
  screen, and wired the overlay's HOME button to it too instead of
  `backToStartScreen` directly, so leaving mid-round from the overlay
  actually resets the round on the backend as well.
- Small Makefile/entrypoint renames (`pac_man.py` <-> `pac-man.py`) going
  back and forth with Achilles' parallel work on the same files.
- Fixed the config path handling for real: `loader.py`'s `CONFIG_PATH` is
  no longer a hardcoded path relative to the project root — `pac_man.py`
  now requires the config path as a CLI argument
  (`python3 pac_man.py <config.json>`), and the Makefile's `run`/`debug`
  targets forward whatever extra argument was passed to `make` (`make run
  config.json`) via a `$(wordlist ...)`/catch-all-target trick instead of
  a fixed `CONFIG` variable.

### Problems / bugs (fixed during the session)
- The cheat-mode double-toggle bug from 2026-09-25 — root cause was
  `check_input_cheat()` reading a stale copy of the expected next input
  instead of the live state, plus never resetting the check array after
  a successful activation.
- Game over always said "GAME OVER" no matter whether you ran out of
  lives or out of time, which was confusing during playtesting once the
  timer was in.
